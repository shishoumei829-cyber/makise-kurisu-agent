# Amadeus 长期目标与路线图

> 上位约束见 [PRODUCT_CHARTER.md](../PRODUCT_CHARTER.md)。本文件回答两个问题：
> 长期要把 Amadeus 建成什么，以及为什么别人抄不走。

## 长期目标（North Star）

Amadeus 是一个**长期在场的本地智能管家**：理解用户、主动接住目标、操作这台电脑解决现实问题、
用证据证明结果、失败会自己恢复，并且始终是「牧濑红莉栖」这同一个主体。

## 竞争力策略：模型不是护城河

管家的执行能力依赖大模型，而模型任何人都调得到。因此产品的防御力必须建在
**换了模型也带不走、竞品从零起步无法补齐**的四层资产上：

| # | 护城河 | 载体 | 对应建设 |
|---|--------|------|----------|
| 1 | 累积私有事实史 | 统一事件 journal（对话/任务/证据/感知同源） | v2 统一事件源 |
| 2 | 可靠性架构 | 无证据不得宣称完成 + 失败自动恢复 + 危险先确认 | v2 恢复循环 |
| 3 | 本机执行履历 | userWorld 记录每个能力在这台机器上的成败，规划器越用越准 | v2→v4 持续 |
| 4 | 人格连续性 | 管家与红莉栖共享同一事实源，是同一个主体 | v2 脑管衔接 |

原则：每加一个新能力，优先问它给哪层护城河添砖，而不是它演示起来多惊艳。

## 版本路线

### v2 — 地基（当前）

1. **统一事件事实源**：butler journal 升级为全局 journal（`source` 区分
   dialogue / perception / task / emotion），对话定稿、行为上报、任务事件全部写入；
   各子系统旧有 json 降级为投影。
2. **脑管衔接**：意识管线 workspace 订阅任务事件——任务等确认/完成/阻塞会进入
   她的意识广播，主动开口从此「有理由」。
3. **恢复循环**：任务执行失败后带着失败证据自动 replan（预算上限），
   耗尽预算才 blocked 并回访用户。
4. 修复 `kernel.getActiveTasks` 缺失。

### v3 — 能力

- 浏览器执行器（受控实例；`web.read_page` / `web.search` / `web.download` 拆细，
  逐个过风险分级与确认门）。
- 桌面能力扩展（超出白名单的应用控制，全部走确认协议）。

### v4 — 考试与个性化

- 能力验收套件：真实任务考场，跑通才允许标记 `available`（宪章第 10 条）。
- userWorld 深化：成败履历反馈到规划偏好，长期个性化。
- 体验评测：北极星指标（免重复背景率 / 有证据完成率 / 自动恢复率）落地为可测数字。

## 迁移纪律

统一事件源动最底层，采用渐进切换：**新写入走 journal，旧读取暂时保留**，
每迁移一个子系统跑一遍完整测试套件，绝不一次性全切。
