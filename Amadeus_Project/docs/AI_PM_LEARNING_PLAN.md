### Day 1：AI PM 是什么 + 产品基础

#### 要搞懂的概念

1. **AI PM vs 传统 PM vs 工程师**
   - 传统 PM：用户需求 → 功能 → 验收 → 数据
   - AI PM 额外负责：模型能力边界、失败体验、评估指标、成本、合规
   - 工程师：实现与 debug；PM 不写代码，但要能定义「什么算做完」

2. **产品基础四件套**
   - Persona（用户画像）
   - User Journey（用户旅程）
   - Jobs to be Done（用户雇产品完成什么）
   - MVP（最小可验证版本）

3. **今日阅读（任选 2 项，约 1 小时）**
   - 吴恩达 *Generative AI for Everyone* 前几节
   - 任意一篇「AI 产品经理是做什么的」入门文章
   - 打开 ChatGPT / 豆包 / Kimi，从用户视角体验 15 分钟，记录 3 个满意点 + 3 个槽点

#### 今日输出

见 `ai_pm_week1_notes.md` Day 1 节。

### Day 2：LLM 与 Prompt（产品视角）

#### 要搞懂的概念

| 概念 | PM 需要知道到什么程度 |
|------|----------------------|
| Token / 上下文窗口 | 对话越长越贵、早期信息可能被挤掉 |
| System / User / Assistant | 规则、人设、历史消息各放哪 |
| 温度 | 创意 vs 稳定的权衡 |
| 流式输出 | 影响用户等待感 |
| 能力边界 | 数学弱、无实时、会幻觉、长程一致性难 |

#### 产品决策题

- 用户要求「永远记住我说过的一切」——敢不敢承诺？风险是什么？
- 回复太长用户烦——砍模型、砍 Prompt 还是砍注入内容？
- 本地部署 vs 云端 API——各适合什么产品承诺？

#### 今日输出

概念卡 5 条 + 1 道判断题（见笔记模板 Day 2）。

### Day 3：RAG 与记忆

#### 要搞懂的概念

**RAG 流程**

```
文档切分 → 向量化 → 检索 → 拼进 Prompt → 生成
```

**PM 必问 5 题**

1. 知识库谁维护？更新频率？
2. 检索不到时怎么说？
3. 是否展示引用来源？
4. 公开知识与私密记忆是否分开？
5. 什么该记、什么不该记？

#### 今日输出

RAG / 长期记忆 / 用户画像 对比表 + 1 个场景题。

---

### Day 4：Agent 与工具调用

#### 要搞懂的概念

**Agent 闭环**

```
意图 → 规划 → 选工具 → 执行 → 看结果 → 再规划或交付
```

**PM 要定义的**

- 能力清单（能做什么 / 不能做什么）
- 权限与确认门
- 完成标准（什么叫「做完了」）
- 失败策略（重试、降级、人工接管）

**决策框架**

| 方案 | 适用 |
|------|------|
| 固定规则 | 步骤确定、代价低 |
| RAG | 问答、查知识 |
| Agent + 工具 | 步骤不确定、要操作外部系统 |
| 微调 | 风格固定、有足够数据 |

#### 今日输出

画一张 Agent 产品流程图 + 写 3 条「产品原则」及验收方式。

---

### Day 5：交互、信任与失败体验

#### 要搞懂的概念

- 信任设计：引用来源、不确定时承认、不伪造已执行的操作
- 失败体验 > 成功体验：错了怎么道歉、撤销、降级
- 主动功能边界：何时主动、用户如何关闭
- 合规：隐私、内容安全、未成年人、情感依赖风险

#### 今日输出

失败场景清单 ≥15 条（分 4 类）+ 每条的产品应对。

---

### Day 6：评估、指标与质量闭环

#### 要搞懂的概念

**指标三层**：业务 → 产品 → AI 质量  

**评估方法**：黄金测试集、人工打分、bad case 回流、回归测试  

#### 今日输出

为你自选的一个 AI 功能定 5～8 个指标 + 上线前检查清单 10 项。

---

### Day 7：商业、竞品与总复盘

#### 要搞懂的概念

- 成本：token、算力、标注、审核
- 护城河：数据、工作流、品牌、评估体系
- 何时不用 AI：规则能搞定、错误代价极高、无法评估

#### 今日任务

拆 2 个竞品 + 闭卷自测 8 题 + 复盘强弱项。

## 附录 D：常见问题

**Q：不会写代码怎么写验收标准？**  
A：写可观察行为。例：「未检索到资料时，不得假装引用了内部文档。」

**Q：没有真实项目怎么办？**  
A：第 2 周可以选一个竞品做「如果我是 PM 的改版方案」，或设计一个假想产品，关键是逻辑完整。

**Q：第 1 周概念不够？**  
A：不延期；薄弱点记入 Day7，第 2 周写 PRD 时回头补。
